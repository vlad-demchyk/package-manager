Rules

Every finding has a rule id. packman fix --rule <id> selects it and checks.disabled in the configuration turns it off. A fix id is selected with fix --fix <id>. Finding and fix titles come from the message catalogue src/i18n/en.ts; the trigger conditions come from docs/rules.md, checked against the ids in the code.

Risk: safe a mechanical edit; review check the diff and the build; breaking crosses a major version. fix takes only safe fixes by default, the rest with --risk review or --risk breaking.

Severity: critical error warning info. check exits with 1 from error up (--fail-on).

The reference needs JavaScript.

Fix ids without a finding

These fixes do not belong to a rule: commands or the TUI create them.

How to turn a rule off

{
  "checks": {
    "disabled": ["npm/range-spec", "spfx/upgrade-available"],
    "ignoreUnused": ["tslib"],
    "ignorePaths": ["src/legacy/**"]
  }
}

policy.exactVersions: false turns npm/range-spec off; packman ignore add <package> adds to checks.ignoreUnused.
