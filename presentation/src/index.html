packman 3.0 · CLI and TUI

Dependencies of many projects, under control

packman finds every project in a repository, detects its stacks (SPFx, React, Angular, Vite ...), picks an installed Node for each one, checks versions, lockfiles and vulnerabilities and shows fixes as a diff. It writes only with --apply, with a backup and a journal. 

$ packman check
Start with the guide Open the simulator

What it does

Stacks and Node

Detects SPFx from the installed packages, not from .yo-rc.json; also React, Angular, Vite, Next.js, Vue, Electron, ESLint, Jest, Vitest. Every project gets its own installed Node (nvm-windows, nvm, fnm, Volta).

Groups and baseline

Projects with the same primary stack (for example, spfx@1.21.1) and Node major form a group, or you define groups in policy.groups. The largest group is the baseline. Inside a group every shared package should converge on the most common version.

Rules with fixes

76 rules: lockfiles, ranges, peer dependencies, SPFx lockstep, compiler, ESLint, Node EOL. Every fix has a risk: safe review breaking.

Safe changes

A diff before writing, --apply to write, a backup of every file, an operation journal, relock with the project Node after version edits.

Shared store

One node_modules installation per group of identical projects, linked with junctions. Drift detection after git pull.

SharePoint

Collects what components need from lists and files, seeds a dev site, loads every component in the workbench or on a real page, walks the property pane and cleans up what it created.

How it works

  1. Project discovery

    Every folder with a package.json down to depth 4 (except node_modules, dist, lib, temp and folders starting with .). The project id is its relative path, for example apps/news-feed.

  2. Analysis

    Stack providers, Node selection, an import scan, npm advisories in one cached request for the whole workspace.

  3. Findings

    Each has a rule id, a severity, evidence and, when possible, a fix with a risk.

  4. Review and write

    Commands that change files show a diff first. Writing happens only with --apply and a confirmation.

Quick start

git clone https://github.com/vlad-demchyk/package-manager.git
cd package-manager
npm ci
npm run build
npm link            # makes the packman and pm commands global

cd C:\repo\workspace
packman check       # read-only
packman             # opens the TUI in a regular terminal

packman runs on Node 22.12+. Your projects stay on their own Node: the launcher finds a newer installed Node for itself. Details in the guide.
