Configuration

Settings

Everything is optional: without the files the defaults apply. The schemas are checked against src/core/config.ts and src/sharepoint/fixtures.ts. An invalid packman.config.json stops the command with exit code 2 and the name of the key.

packman.config.json

Lives at the workspace root. packman init creates it (with groups right away with --with-groups); profile generate --write adds profiles, upgrade --apply the target, ignore add the ignore list.

Key Type Default What it sets
language auto, en, it, uk auto Language when --lang is not given. auto: PACKMAN_LANG, LC_ALL, LC_MESSAGES, LANG, then the OS locale.
projects object see below Project discovery.
policy object see below Exact versions and version groups.
profiles name → profile {} Dependency profiles (2.x dependencies-config.js).
target object {} Repository target versions.
checks object see below Disabled rules and scan exclusions.
$schema string - Ignored, allowed for editors.

projects

Key Default What it sets
include ["**"] Glob masks of project ids (picomatch).
exclude [] Masks to skip.
maxDepth 4 Search depth, 0-12; --depth overrides it.
includeRoot false Also analyze the root package.json. A repository whose root is the only project is always analyzed.
requiredFiles [] Files or folders a project must have, for example ["src", "tsconfig.json"].
match - A regular expression for the project id.

Never walked: folders starting with ., node_modules, .git, .packman, dist, lib, lib-amd, lib-commonjs, lib-dts, lib-esm, temp, release, coverage, .next, .turbo, .cache.

policy

Key Default What it sets
exactVersions true Report ^, ~ and other ranges (npm/range-spec); false turns the rule off.
groups[].name required Group name.
groups[].stack - Only projects with this primary stack (spfx, react, ... or node when there is no stack).
groups[].projects required Project id masks (at least one).
groups[].node - Node version or range of the group (valid semver). It becomes a requirement of every member; npm commands use a Node that satisfies it.
groups[].pins {} Versions every member must be on; otherwise policy/pin-violation.
  • A project belongs to the first group whose masks and stack match it. The primary stack is the first one found of spfx, angular, next, electron, vue, vite, react, typescript, eslint, vitest, jest.
  • The rest is grouped automatically as <stack>@<version> / node <major>. The group with the most projects becomes the baseline.
  • In a group of two or more projects, a package in several versions gives policy/group-divergence with a target: the most common version, the highest on a tie.

profiles

Key What it does
stack, projects Which projects it applies to (masks are required).
dependencies Version in dependencies when the package is declared or imported.
devDependencies Always present in devDependencies with this version.
conditionalDevDependencies Version in devDependencies when the package is declared or imported.
deprecated Remove from every dependency section.
scripts, engines, overrides Set as given.
tsconfig Merged into tsconfig.json leaf by leaf (arrays are leaves).

Every profile whose masks and stack match applies; they merge in declaration order, the later one wins, and profiles named packman-* (written by upgrade) merge last. Deviations become profile/* findings; packman profile apply applies them all.

target

Repository target versions, usually written by packman upgrade --apply (only without -p/-x). Keys: spfx, node, react, angular, next, electron, vue, vite, typescript, eslint, jest, vitest. Values are exact versions only; a range is rejected. target.node gives policy/target-node, target.<stack> gives policy/target-stack.

checks

Key What it sets
disabled Rule ids removed from every report (exact ids, no masks).
ignoreUnused Packages never reported as unused (packman ignore add/remove/list).
ignorePaths Masks relative to every project, excluded from the source scan (for example, test/**).

Full example

{
  "language": "en",
  "target": { "spfx": "1.21.1", "node": "22.19.0" },
  "projects": {
    "include": ["**"],
    "exclude": ["legacy-*"],
    "maxDepth": 4,
    "includeRoot": false,
    "requiredFiles": ["src"]
  },
  "profiles": {
    "spfx121": {
      "stack": "spfx",
      "projects": ["apps/*"],
      "dependencies": { "react": "17.0.1", "@pnp/sp": "4.12.0" },
      "devDependencies": { "@types/webpack-env": "1.15.3" },
      "deprecated": ["moment"],
      "engines": { "node": ">=22.14.0 <23.0.0" },
      "tsconfig": { "compilerOptions": { "skipLibCheck": true } }
    }
  },
  "policy": {
    "exactVersions": true,
    "groups": [
      { "name": "spfx-1.21", "stack": "spfx", "projects": ["apps/*"], "node": "22.19.0", "pins": { "react": "17.0.1" } }
    ]
  },
  "checks": {
    "disabled": ["spfx/upgrade-available"],
    "ignoreUnused": ["@microsoft/sp-office-ui-fabric-core"],
    "ignorePaths": ["test/**"]
  }
}

packman.sharepoint.json

Fixtures for packman sp, JSON with comments. sp requirements --write creates and extends the file; field types, choices, items and file contents are filled in by hand.

Key What it sets
site Dev site URL; --site overrides it. Never production.
lists[] title, template (generic, documents, events, pictures), fields, items, usedBy, writes.
lists[].fields[] name (^[A-Za-z_]\w*$), type: Text, Note, Number, Boolean, DateTime, Choice, MultiChoice, URL, User, Lookup; choices; list for Lookup.
files[] path relative to the site, content or from (a workspace file) or placeholder (a PNG colour).
contentTypes[] name, parent (default Site Page), list (default Site Pages), fields.
pages[] name (*.aspx), title, contentType, fields, news, list.
webs[] Subsites: url, title, language (LCID, default 1033), template (default STS#3) and their own lists, files, contentTypes, pages.
components.<alias> How sp test hosts a component, keyed by the manifest alias: query ({List/Title} becomes an item id), properties, page, known (known issues that do not fail the run), note. See below.

Components: properties and page

  • properties: an object laid over the web part's first preconfigured entry in the manifest, such as a dropdown key or the items a collection editor would fill. The toolbox adds the web part with them.
  • page: a site-relative .aspx path, for example SitePages/test-news-1.aspx or news/SitePages/test-news-1.aspx in a subsite. The web part is embedded in that page's canvas in a new one-column section and runs with the page's real context (list item, list, canvas). --properties does not run on pages.
  • Both change only what the browser receives (the debug manifests, the page HTML); nothing is saved on the site.

Item values

  • "@me": the id of the current user on the site; "@aad": their Entra object id.
  • { "lookup": "<Title>" } in a Lookup field: the id of the item with that Title in the target list.
  • "today", "now", "today+3d", "now-2h": an ISO date.
  • In libraries the item identity is file; content or placeholder sets the content. 
{
  "site": "https://contoso.sharepoint.com/sites/dev",
  "lists": [
    { "title": "Events", "writes": true,
      "fields": [{ "name": "EventDate", "type": "DateTime" }, { "name": "Organizer", "type": "User" }],
      "items": [{ "Title": "[test] Kick-off", "EventDate": "today+3d", "Organizer": "@me" }] }
  ],
  "files": [{ "path": "SiteAssets/footer/contacts.json", "content": { "email": "team@contoso.com" } }],
  "contentTypes": [{ "name": "News Page", "fields": [{ "name": "PublishDate", "type": "DateTime" }] }],
  "pages": [
    { "name": "test-news-1.aspx", "title": "[test] News 1", "contentType": "News Page",
      "news": true, "fields": { "PublishDate": "today" } }
  ],
  "components": {
    "TeamCalendarWebPart": {
      "query": "eventId={Events/[test] Kick-off}",
      "properties": { "view": "month", "listTitle": "Events" },
      "known": ["PnPTelemetry"]
    },
    "NewsBannerWebPart": { "page": "SitePages/test-news-1.aspx" }
  }
}

Environment variables

Variable Effect
PACKMAN_LANG Language for auto.
PACKMAN_DATA_DIR Folder of updated data; an empty value turns updated data off.
PACKMAN_BROWSER Chromium browser for packman sp.
PACKMAN_DEBUG Print the stack of unexpected errors.
CI Turns the automatic TUI off.
NVM_HOME, NVM_DIR, FNM_DIR, VOLTA_HOME Where to look for installed Node versions.

What packman writes

Path Contents
.packman/backups/<time>/ Copies of files before edits.
.packman/journal.jsonl Operation journal (packman log).
.packman/store/<key>/, .packman/links.json Stores and link records.
.packman/trash/ Package copies npm left in linked folders.
.packman/verified/ Verified version sets of projects and stores.
.packman/sharepoint/seeded.json What sp seed created, per site.
.packman/validation/<time>-sharepoint/ sp test results.
%LOCALAPPDATA%\packman (Windows), ~/.cache/packman data/ updated data, cache/ advisories and registry documents (12 h), browser/ the browser profile for sp.
