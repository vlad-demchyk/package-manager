# Rules

Every finding packman produces, grouped by the module that produces it. Each entry gives the
`ruleId`, the severity, what triggers it and the fixes it carries (fix id and risk). Fix ids are what
`packman fix --fix <id>` selects; rule ids are what `packman fix --rule <id>` and `checks.disabled`
use.

Risk levels: `safe` (mechanical), `review` (check the diff and build), `breaking` (crosses a major).
`packman fix` includes only `safe` fixes unless `--risk` says otherwise.

Severities: `critical`, `error`, `warning`, `info`. `check` exits 1 at `error` or worse by default.

## Usage scan

Source: `checkUsage` in `src/providers/npm.ts`. Skipped with `--no-usage` and when no source file
was scanned. The scan (`src/scan/sources.ts`) reads `.ts`, `.tsx`, `.mts`, `.cts`, `.js`, `.jsx`,

| Rule                          | Severity | Trigger                                                                                                                                                                                                                                                 | Fixes                                                                                                           |
| ----------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |

| `npm/unused-dev-dependency`   | info     | A `devDependencies` entry is not used.                                                                                                                                                                                                                  | `npm/unused-dev-dependency` (review): removes them.                                                             |

A package counts as used when any of these holds: imported by code or styles (`~pkg`, `pkg:`
included); listed in `checks.ignoreUnused`; implied by the stack (SPFx scaffold packages for the
version, toolchain, component types and React usage, plus `tslib` and
`@microsoft/sp-office-ui-fabric-core`); implied by config files, npm scripts (including executables
of installed packages) or plugin naming of configured tools (`src/scan/implicit.ts`); required by
another locked package (a top-level declaration then pins a transitive version); `@types/*`,
`@microsoft/rush-stack-compiler-*`, `@microsoft/sp-build-web` or `tslib`.

## Security

Source: `src/security/exposure.ts`, `src/security/advisories.ts`. Skipped with `--no-security`.

| Rule                             | Severity              | Trigger                                                                                                                                                                                                                                                                                                                                      | Fixes |
| -------------------------------- | --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----- |
| `security/package-vulnerability` | per group (see below) | The npm bulk advisories endpoint (`registry.npmjs.org/-/npm/v1/security/advisories/bulk`, one request for every name and version in the workspace, cached 12 hours) reports advisories for a locked or installed version. One finding per resulting severity; evidence lists package, version, advisory, direct/transitive, context and URL. | none  |
| `security/node-vulnerable`       | worst CVE, adjusted   | The selected Node version has known core CVEs in `node-vulns.json`.                                                                                                                                                                                                                                                                          | none  |

Package severity: advisory `critical` -> critical, `high` -> error, `moderate`/`medium` -> warning,
others info; then one level lower when every copy is a dev dependency (`build only`), or one level
higher when the package or advisory is network related (listed in `network.json` or a title about
SSRF, redirects, proxies, cookies, headers, TLS, ...) and the project makes network calls.

Node severity: the worst CVE severity, one level lower for browser projects (reported as build
machine only), one level higher for server projects that accept requests (`express`, `@nestjs/core`,
`fastify`, `koa`, `@hapi/hapi`, `next`, `hono` in `dependencies`) when a CVE concerns HTTP, TLS, DNS
and similar areas.

Exposure: `server` when the manifest has `bin`, the stack is Next.js or Electron, or `express`,
`@nestjs/core` or `fastify` is declared; `browser` for SPFx, React, Vue, Angular and Vite; otherwise
`unknown`.

## Disabling rules

Add rule ids to `checks.disabled` in `packman.config.json`. Disabled findings are removed from every
report, JSON output and fix selection.
